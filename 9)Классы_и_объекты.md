## 1. Теоретическая шпаргалка: основы объектно-ориентированного программирования

Класс — это пользовательский ссылочный тип данных (`reference type`), выступающий шаблоном или чертежом для создания объектов. Объект — это конкретный экземпляр класса, размещаемый в управляемой куче (`heap`) и обладающий собственным состоянием и поведением.

### 1.1. Модификаторы доступа

Определяют область видимости компонентов класса:

- `public` — открытый доступ из любого места программы.
- `private` — закрытый доступ; член класса доступен только внутри тела самого этого класса (уровень доступа по умолчанию).

### 1.2. Поля и инкапсуляция

Поле — переменная, объявленная внутри класса для хранения внутреннего состояния. Для защиты от некорректных значений поля делают закрытыми (`private`), предотвращая прямой доступ извне:

```csharp
class Character
{
    // Закрытые поля (инкапсулированное состояние)
    private string _name;
    private int _health;
}
```

### 1.3. Свойства (Properties)

Свойства предоставляют безопасный интерфейс доступа к полям через блоки доступа (`get` — чтение, `set` — запись). Они позволяют проверять входящие данные перед сохранением:

```csharp
class Character
{
    private int _health;

    // Полномочное свойство с валидацией
    public int Health
    {
        get { return _health; }
        set
        {
            if (value < 0) _health = 0;
            else if (value > 100) _health = 100;
            else _health = value;
        }
    }

    // Автоматическое свойство (компилятор сам создает скрытое поле)
    public string Name { get; set; }

    // Свойство только для чтения (вычисляемое)
    public bool IsAlive => _health > 0;
}
```

### 1.4. Конструкторы (Constructors)

Конструктор — специальный метод, вызываемый автоматически при создании объекта оператором `new`. Конструктор инициализирует состояние объекта, не возвращает значение и имеет имя, строго совпадающее с именем класса.

Ключевое слово `this` указывает на текущий экземпляр класса, позволяя разграничивать имена полей и входящих аргументов:

```csharp
class Character
{
    public string Name { get; set; }
    public int Health { get; set; }

    // Конструктор по умолчанию (без параметров)
    public Character()
    {
        Name = "Неизвестный";
        Health = 100;
    }

    // Параметризованный конструктор
    public Character(string name, int health)
    {
        this.Name = name;
        this.Health = health;
    }
}
```

### 1.5. Методы экземпляра

Методы определяют поведение объекта и имеют прямой доступ к его внутренним полям и свойствам:

```csharp
class Character
{
    public int Health { get; set; }

    public void TakeDamage(int damage)
    {
        if (damage > 0)
        {
            Health = Math.Max(0, Health - damage);
            Console.WriteLine($"Получено урона: {damage}. Остаток HP: {Health}");
        }
    }

    public void DisplayInfo()
    {
        Console.WriteLine($"[Персонаж] HP: {Health}");
    }
}
```

## 2. Организация парной разработки

Студенты проектируют систему из взаимосвязанных классов без использования статических полей.

- **Студент 1 (Data & Validation Architect):**
  - Проектирует класс сущности: объявляет закрытые поля, обеспечивает инкапсуляцию.
  - Реализует свойства с проверкой граничных значений в блоках `set`.
  - Пишет конструктор по умолчанию и конструктор с параметрами (с использованием `this`).

- **Студент 2 (Behavior & Simulation Engineer):**
  - Разрабатывает методы поведения класса (изменение состояния, расчет эффективности, форматированный вывод).
  - В методе `Main` создает массив объектов (`Class[]`), инициализирует их разными конструкторами.
  - Моделирует взаимодействие объектов в цикле (обработка событий, вызов методов экземпляров).

## 3. Единое практическое задание

Каждая команда разрабатывает автономную объектную модель в соответствии с выбранным вариантом. Проект должен содержать:

1. **Класс сущности:**
   - Не менее 4 закрытых полей (`private`).
   - Свойства (`public`) с проверкой диапазонов в `set` (числовые значения не должны уходить в недопустимые отрицательные или запредельные зоны).
   - Вычисляемое свойство только для чтения (`get` без `set`), возвращающее статус или агрегированный показатель.
   - Минимум 2 конструктора: конструктор по умолчанию (с корректными базовыми значениями) и конструктор со всеми параметрами.
2. **Методы поведения:**
   - Метод изменения состояния (расход ресурса, получение урона, нагрев, износ и т.д.).
   - Метод восстановления или пополнения ресурса с контролем переполнения.
   - Метод `PrintStatus()`, форматированно выводящий все параметры объекта в консоль.
3. **Моделирование в Main:**
   - Создать массив минимум из 3 объектов данного класса с разными начальными параметрами.
   - В цикле смоделировать 3–4 шага взаимодействия или событийной нагрузки на объекты.
   - Вывести итоговое состояние всех объектов после симуляции.

## 4. Варианты заданий

---

### Вариант 1. Бортовой аккумулятор электромобиля (`BatteryPack`)

- **Поля:** емкость в кВт·ч, текущий уровень заряда в %, температура батареи, количество циклов перезарядки.
- **Свойства:** валидация заряда (0–100%), валидация температуры (-30..+70 °C); свойство только для чтения `IsOverheated` (температура > 55 °C).
- **Методы:** `ConsumeCharge(double kwh)`, `Recharge(double kwh)`, `PrintStatus()`.
- **Сценарий в Main:** массив из 3 батарей с разным износом при поездке в мороз и скоростной зарядке.

---

### Вариант 2. Автономный складской дрон-погрузчик (`WarehouseDrone`)

- **Поля:** серийный номер, грузоподъемность в кг, текущий вес груза, уровень заряда батареи.
- **Свойства:** валидация веса груза (не может превышать грузоподъемность), заряд (0–100%); свойство только для чтения `IsAvailable` (заряд > 20% и груз равен 0).
- **Методы:** `LoadCargo(double weight)`, `UnloadCargo()`, `PrintStatus()`.
- **Сценарий в Main:** 3 дрона распределяют поступающие на склад ящики разной массы.

---

### Вариант 3. Двигатель магистрального тягача (`TruckEngine`)

- **Поля:** рабочий объем (л), обороты в минуту (RPM), температура охлаждающей жидкости, уровень моторного масла (%).
- **Свойства:** валидация RPM (600–3500), уровень масла (0–100%); свойство только для чтения `WarningOilLow` (масло < 15%).
- **Методы:** `Accelerate(int targetRpm)`, `Idle()`, `PrintStatus()`.
- **Сценарий в Main:** моделирование движения 3 грузовиков на затяжном подъеме в гору.

---

### Вариант 4. Кофейный автомат самообслуживания (`CoffeeMachine`)

- **Поля:** запас воды (мл), запас зерен (г), заполненность контейнера жмыха (порции), выручка (руб).
- **Свойства:** вода (0–2000 мл), зерна (0–1000 г); свойство только для чтения `NeedsService` (жмых >= 15 порций или вода < 150 мл).
- **Методы:** `MakeEspresso()`, `CleanWasteContainer()`, `PrintStatus()`.
- **Сценарий в Main:** моделирование утреннего потока клиентов для 3 кофемашин в бизнес-центре.

---

### Вариант 5. Телекоммуникационный маршрутизатор (`NetworkRouter`)

- **Поля:** IP-адрес шлюза, пропускная способность (Мбит/с), объем переданных данных (Гб), число активных соединений.
- **Свойства:** число соединений (0–256), пропускная способность (> 0); свойство только для чтения `IsOverloaded` (соединения > 200).
- **Методы:** `ConnectDevice()`, `DisconnectDevice()`, `PrintStatus()`.
- **Сценарий в Main:** балансировка нагрузки между 3 маршрутизаторами в офисной сети.

---

### Вариант 6. Банковский депозитный сейф (`BankSafeBox`)

- **Поля:** номер ячейки, сумма вклада, процентная ставка, статус блокировки замка.
- **Свойства:** сумма вклада (не может быть отрицательной), ставка (0–30%); свойство только для чтения `IsAccessible` (не заблокирован и сумма >= 0).
- **Методы:** `Deposit(decimal amount)`, `Withdraw(decimal amount)`, `PrintStatus()`.
- **Сценарий в Main:** операции начисления процентов и снятия наличных для 3 клиентов банка.

---

### Вариант 7. Тепличный климатический контроллер (`GreenhouseModule`)

- **Поля:** влажность воздуха (%), влажность почвы (%), температура (°C), запас воды в резервуаре полива (л).
- **Свойства:** влажность (0–100%), температура (0–50 °C); свойство только для чтения `DroughtRisk` (почва < 20% и резервуар < 5 л).
- **Методы:** `Irrigate(double liters)`, `HeatUp(double degrees)`, `PrintStatus()`.
- **Сценарий в Main:** засушливый день для 3 теплиц с томатами, огурцами и клубникой.

---

### Вариант 8. Смарт-часы фитнес-трекера (`FitnessTracker`)

- **Поля:** текущий пульс (bpm), пройденные шаги, сожженные калории, заряд аккумулятора (%).
- **Свойства:** пульс (40–220 bpm), шаги (>= 0); свойство только для чтения `IsCardioZone` (пульс > 130 bpm).
- **Методы:** `LogSteps(int steps)`, `ResetDailyStats()`, `PrintStatus()`.
- **Сценарий в Main:** 3 спортсмена на утренней тренировке разной интенсивности.

---

### Вариант 9. Торговый автомат напитков (`VendingMachine`)

- **Поля:** число бутылок в наличии, цена за штуку, внесенный клиентом кредит, сумма наличных в сейфе.
- **Свойства:** бутылки (0–60), кредит (>= 0); свойство только для чтения `IsSoldOut` (бутылок 0).
- **Методы:** `InsertMoney(decimal cash)`, `DispenseDrink()`, `PrintStatus()`.
- **Сценарий в Main:** покупки напитков студентами на перемене у 3 автоматов в холле.

---

### Вариант 10. Планетарный зонд-луноход (`SpaceRover`)

- **Поля:** целостность шасси (%), температура корпуса (K), емкость солнечных панелей (Вт), радиосигнал (%).
- **Свойства:** целостность (0–100%), сигнал (0–100%); свойство только для чтения `IsCritical` (целостность < 20% или сигнал == 0).
- **Методы:** `MoveThroughCraters(int distanceMeters)`, `RechargeFromSun()`, `PrintStatus()`.
- **Сценарий в Main:** преодоление лунного кратера группой из 3 исследовательских зондов.

---

### Вариант 11. Городской прокатный электросамокат (`ElectricScooter`)

- **Поля:** серийный номер, пробег (км), уровень заряда батареи (%), флаг блокировки колеса.
- **Свойства:** заряд (0–100%), пробег (>= 0); свойство только для чтения `CanRent` (заряд > 15% и колесо заблокировано).
- **Методы:** `StartRide()`, `EndRide(double distanceKm)`, `PrintStatus()`.
- **Сценарий в Main:** 3 самоката арендуются пользователями для поездок по центру города.

---

### Вариант 12. Реактор атомной электростанции (`NuclearReactorCore`)

- **Поля:** тепловая мощность (МВт), положение стержней поглотителя (%), температура теплоносителя (°C), давление в контуре (атм).
- **Свойства:** стержни (0–100%), давление (0–200 атм); свойство только для чтения `ScramRequired` (температура > 330 °C).
- **Методы:** `LowerRods(int percent)`, `RaiseRods(int percent)`, `PrintStatus()`.
- **Сценарий в Main:** моделирование изменения нагрузки в энергосети для 3 энергоблоков АЭС.

### Вариант 13. Судовой дизель-генератор (`MarineGenerator`)

- **Поля:** вырабатываемая мощность (кВт), остаток солярки в баке (л), моточасы до техобслуживания, температура выхлопных газов (°C).
- **Свойства:** топливо (0–5000 л), моточасы (>= 0); свойство только для чтения `NeedsService` (моточасы <= 10).
- **Методы:** `Operate(int hours, double loadKw)`, `Refuel(double liters)`, `PrintStatus()`.
- **Сценарий в Main:** переход судна через шторм с электроснабжением от 3 генераторов.

---

### Вариант 14. Мобильный аппарат искусственной вентиляции легких (`VentilatorUnit`)

- **Поля:** давление кислорода (см вод. ст.), частота дыхания (вдох/мин), процент кислорода в смеси (FiO2, %), резерв баллона (бар).
- **Свойства:** FiO2 (21–100%), давление (5–40 см вод. ст.); свойство только для чтения `OxygenLowAlarm` (баллон < 20 бар).
- **Методы:** `DeliverBreath()`, `ReplaceCylinder(int newBars)`, `PrintStatus()`.
- **Сценарий в Main:** работа 3 аппаратов ИВЛ в реанимационном отделении больницы.

### Вариант 15. Промышленный плавильный ковш металлургического завода (`SmeltingLadle`)

- **Поля:** масса расплавленной стали (тонны), текущая температура металла (°C), износ огнеупорной футеровки (%), время с момента выпуска (мин).
- **Свойства:** температура (1200–1750 °C), износ (0–100%); свойство только для чтения `RefractoryBreachRisk` (износ > 85%).
- **Методы:** `PourSteel(double tons)`, `HeatMetal(int degrees)`, `PrintStatus()`.
- **Сценарий в Main:** транспортировка жидкой стали от конвертера к установке непрерывной разливки для 3 ковшей.
