## 1. Теоретическая шпаргалка: полиморфизм в C#

Полиморфизм — принцип объектно-ориентированного программирования, позволяющий использовать единый программный интерфейс для взаимодействия с объектами различных конкретных типов, обеспечивая специфичное поведение каждого типа во время выполнения программы.

### 1.1. Статический и динамический полиморфизм

В C# выделяют две ключевые формы реализации полиморфного поведения:

- **Статический (компиляционный) полиморфизм:** реализуется через перегрузку методов (`overloading`). Решение о том, какая версия метода вызывается, принимается компилятором на этапе сборки по количеству и типам аргументов.
- **Динамический (рантайм) полиморфизм:** реализуется через позднее связывание при наследовании (`virtual` / `override` / `abstract`). Конкретная версия метода определяется средой выполнения (`CLR`) в момент работы программы на основе фактического типа объекта в куче, а не типа переменной-ссылки.

### 1.2. Виртуальные члены: virtual и override

Для включения механизма позднего связывания метод базового класса объявляется с модификатором `virtual`, а производный класс замещает его логику через `override`:

```csharp
public class Alert
{
    public virtual void Send()
    {
        Console.WriteLine("Базовое системное уведомление.");
    }
}

public class SmsAlert : Alert
{
    public override void Send()
    {
        Console.WriteLine("Отправка SMS через GSM-шлюз.");
    }
}
```

При обращении к объекту через ссылку предка `Alert alert = new SmsAlert(); alert.Send();` среда CLR найдет и выполнит реализацию из `SmsAlert`.

### 1.3. Абстрактные классы и методы (abstract)

Абстрактный класс — это недостроенный базовый шаблон, экземпляр которого нельзя создать напрямую через `new`. Он служит фундаментом для проектирования полиморфных семейств:

- Абстрактный метод **не имеет реализации** в базовом классе (оканчивается точкой с запятой).
- Все неабстрактные классы-потомки **обязаны** переопределить абстрактные методы через `override`.
- Абстрактный класс может содержать как абстрактные, так и обычные или виртуальные методы, поля и свойства.

```csharp
public abstract class PaymentProcessor
{
    public string Currency { get; set; } = "RUB";

    // Абстрактный метод: реализация у потомков строго обязательна
    public abstract bool Process(decimal amount);

    // Обычный готовый метод, общий для всех
    public void PrintReceipt(decimal amount)
    {
        Console.WriteLine($"Чек: {amount} {Currency}");
    }
}
```

### 1.4. Переопределение (override) против сокрытия (new)

Ключевое слово `new` разрывает цепочку виртуального вызова, скрывая родительский метод в производном классе:

- При использовании `override` виртуальная таблица методов обновляется: вызов через ссылку базового типа всегда выполняет метод потомка.
- При использовании `new` метод потомка вызывается **только** тогда, когда ссылка имеет тип потомка. Если обращение идет через ссылку базового типа, выполнится родительский метод.

```csharp
public class BaseSensor
{
    public virtual void Read() => Console.WriteLine("Base Read");
}

public class CustomSensor : BaseSensor
{
    public new void Read() => Console.WriteLine("Custom Read via New");
}

BaseSensor s = new CustomSensor();
s.Read(); // Выведет "Base Read", так как 'new' скрыл метод только для прямых ссылок CustomSensor
```

## 2. Архитектура практического задания

Разрабатывается полиморфное процессинговое ядро **«Мультиканальный шлюз уведомлений и тревог» (`NotificationGateway`)**.

### Иерархия классов:

- **`NotificationChannel` (Абстрактный базовый класс):** задает контракт передачи сообщений, ведет аудит попыток отправки и содержит общий виртуальный метод форматирования.
- **`EmailChannel` (Производный класс 1):** отправка писем с имитацией валидации почтового домена.
- **`TelegramChannel` (Производный класс 2):** отправка в мессенджер с поддержкой Markdown-разметки и подсчетом символов.
- **`SirenAlarmChannel` (Производный класс 3):** сирена экстренного оповещения с сокрытием (`new`) метода форматирования и вызовом звукового сигнала.

## 3. Технические требования к реализации

### Шаг 1. Абстрактный класс `NotificationChannel`

1. Поля и свойства:
   - `protected string ChannelName;` — защищенное наименование шлюза;
   - `public int DeliveredCount { get; protected set; }` — счетчик успешно доставленных оповещений;
   - `public abstract bool IsOnline { get; }` — абстрактное свойство проверки доступности канала.
2. Конструктор:
   - `public NotificationChannel(string name)` — инициализирует имя канала.
3. Методы:
   - `public abstract bool Deliver(string recipient, string message);` — абстрактный метод отправки;
   - `public virtual string FormatPayload(string rawMessage)` — виртуальный метод, возвращающий строку вида `"[ChannelName] rawMessage"`;
   - `public void PrintAudit()` — обычный метод, выводящий итоговый отчет доставленных сообщений по каналу.

### Шаг 2. Класс `EmailChannel`

1. Наследуется от `NotificationChannel`.
2. Реализация членов:
   - Свойство `IsOnline`: возвращает `true`, если почтовый SMTP-сервер доступен;
   - Конструктор: принимает `name` и передает в `base(name)`;
   - `public override string FormatPayload(string rawMessage)`: вызывает базовое форматирование `base.FormatPayload(rawMessage)` и добавляет к нему почтовый колонтитул: `"\n---\nС уважением, Почтовый Сервис"`;
   - `public override bool Deliver(string recipient, string message)`: проверяет наличие символа `@` в адресе получателя. Если символ отсутствует, отправка бракуется; иначе счетчик `DeliveredCount` увеличивается на 1, и сообщение выводится в консоль.

### Шаг 3. Класс `TelegramChannel`

1. Наследуется от `NotificationChannel`.
2. Реализация членов:
   - Свойство `IsOnline`: возвращает `true`;
   - Конструктор: принимает `name` и токен бота, передает имя в `base(name)`;
   - `public override bool Deliver(string recipient, string message)`: проверяет, чтобы `recipient` начинался с символа `@` (юзернейм), а длина сообщения не превышала 100 символов. При успехе увеличивает `DeliveredCount` и выводит отформатированный текст.

### Шаг 4. Класс `SirenAlarmChannel`

1. Наследуется от `NotificationChannel`.
2. Реализация членов:
   - Свойство `IsOnline`: возвращает `true`, если уровень звукового реле выше критического порога;
   - Конструктор: вызывает `base("Звуковая Сирена")`;
   - `public new string FormatPayload(string rawMessage)`: выполняет **сокрытие** (`new`) базового метода, переводя весь текст сообщения в верхний регистр с добавлением меток: `"[ТРЕВОГА МЧС]: " + rawMessage.ToUpper()`;
   - `public override bool Deliver(string recipient, string message)`: игнорирует получателя, выводит в консоль звуковой сигнал тревоги (через `Console.Beep()` или текстовый спецсимвол) и инкрементирует `DeliveredCount`.

### Шаг 5. Полиморфный диспетчер в `Program.cs`

В методе `Main`:

1. Создать массив абстрактного типа `NotificationChannel[] channels = new NotificationChannel[3];`, разместив в нем по одному экземпляру каждого канала.
2. Продемонстрировать позднее связывание:
   - В цикле обойти массив и отправить тестовое оповещение `"Внимание: регламентные технические работы в серверной!"` разным получателям.
3. Продемонстрировать разницу между `override` и `new`:
   - Вызвать метод `FormatPayload` для объекта сирены через ссылку базового типа `NotificationChannel`. Зафиксировать, что вызвалась базовая логика;
   - Привести сирену к прямому типу `SirenAlarmChannel` и вызвать `FormatPayload`. Зафиксировать, что сработало сокрытие (`new`).
4. В цикле вызвать единый метод `PrintAudit()` для каждого элемента массива, показав полиморфную согласованность счетчиков.
