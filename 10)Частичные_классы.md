## 1. Теоретическая шпаргалка: частичные классы и методы

Модификатор `partial` позволяет разделить определение одного и того же класса, структуры или интерфейса на два или более физических файла исходного кода (`.cs`).

Во время сборки проекта компилятор C# объединяет все части (`partial parts`) в единый класс в сборке. В рантайме этот класс ведет себя точно так же, как если бы он был написан в одном монолитном файле.

### 1.1. Правила объявления partial-классов

1. Все части обязаны иметь модификатор `partial` перед ключевым словом `class`.
2. Все части должны принадлежать **одному пространству имен** (`namespace`).
3. Имя класса и модификаторы доступа (например, `public`) во всех частях обязаны строго совпадать.
4. Поля и закрытые методы, объявленные в одной части класса, напрямую доступны во всех остальных частях этого же класса без создания экземпляров.

```csharp
// Файл: Player.Data.cs
namespace GameCore
{
    public partial class Player
    {
        private int _health;
        public string Nickname { get; set; }
    }
}

// Файл: Player.Actions.cs
namespace GameCore
{
    public partial class Player
    {
        public void Heal(int amount)
        {
            _health += amount; // Прямой доступ к _health из другого файла
        }
    }
}
```

### 1.2. Для чего используются частичные классы

- **Разделение сфер ответственности (Separation of Concerns):** хранение данных и валидации в одном файле, бизнес-логики и расчетов — во втором, интерфейса и графического вывода — в третьем.
- **Работа с автогенерируемым кодом:** генераторы кода (GUI-конструкторы WPF/WinForms, ORM Entity Framework) генерируют одну часть класса, а разработчик дописывает свою логику в другой части, не рискуя потерять код при повторной автогенерации.
- **Удобство командной разработки:** несколько программистов могут одновременно работать над разными аспектами одной крупной сущности в разных файлах проекта без конфликтов слияния в Git.

### 1.3. Частичные методы (Partial Methods)

Частичный метод позволяет объявить сигнатуру метода в одной части класса, а его тело (реализацию) написать в другой части (или вовсе опустить).

```csharp
// Файл 1: Объявление
public partial class Logger
{
    partial void OnLogCompleted(string message); // Сигнатура
}

// Файл 2: Реализация (необязательна)
public partial class Logger
{
    partial void OnLogCompleted(string message)
    {
        Console.WriteLine($"Событие записано: {message}");
    }
}
```

_Если реализация частичного метода отсутствует, компилятор C# полностью вырезает вызовы этого метода и его сигнатуру из результирующего бинарного файла._

## 2. Архитектура практического задания

Цель работы — разработать программный комплекс **«Бортовой модуль космического шаттла» (`SpaceShuttle`)**, распределив его архитектуру строго по **четырем отдельным `.cs` файлам**.

### Структура файлов проекта:

1. `SpaceShuttle.Core.cs` — закрытые поля, свойства с валидацией, конструкторы.
2. `SpaceShuttle.Engines.cs` — логика двигательной установки, расход топлива, маневры.
3. `SpaceShuttle.Diagnostics.cs` — бортовой журнал, расчет запаса хода, частичный метод логирования.
4. `Program.cs` — точка входа (`Main`), демонстрация работы объекта шаттла.

## 3. Пошаговые технические требования

### Файл 1: `SpaceShuttle.Core.cs` (Ядро и данные)

Объявить `public partial class SpaceShuttle`:

- **Поля:**
  - `_fuelKg` (`double`) — масса топлива в баках;
  - `_oxygenHours` (`double`) — запас кислорода системы жизнеобеспечения в часах;
  - `_hullIntegrity` (`int`) — прочность корпуса в процентах (0–100).
- **Свойства:**
  - `ShuttleName` (`string`, автосвойство) — название челнока;
  - `FuelKg` с проверкой: топливо не может быть меньше 0;
  - `HullIntegrity` с проверкой: ограничение в диапазоне от 0 до 100;
  - `IsOperational` (только для чтения, `bool`): возвращает `true`, если `_hullIntegrity > 15` и `_oxygenHours > 0`.
- **Конструкторы:**
  - Конструктор с параметрами: принимает имя, запас топлива, запас кислорода и прочность корпуса, инициализируя поля с использованием `this`.

---

### Файл 2: `SpaceShuttle.Engines.cs` (Двигатели и физика полета)

Дополнить `public partial class SpaceShuttle`:

- **Методы:**
  - `ExecuteOrbitalBurn(double burnTimeSeconds, double thrustPower)` — моделирует работу маршевого двигателя:
    - Расход топлива вычисляется по формуле: `burnTimeSeconds * thrustPower * 2.5`.
    - Если топлива недостаточно, маневр прерывается с выводом ошибки в консоль.
    - При успешном прожиге топливо списывается, а износ корпуса увеличивается на 1% за каждые 10 секунд работы.
  - `PerformAtmosphericEntry()` — маневр входа в плотные слои атмосферы:
    - Снижает прочность корпуса `_hullIntegrity` на случайную величину от 10% до 25%.
    - Списывает 1.5 часа запаса кислорода.

---

### Файл 3: `SpaceShuttle.Diagnostics.cs` (Диагностика и события)

Дополнить `public partial class SpaceShuttle`:

- **Частичный метод:**
  - Объявить сигнатуру: `partial void OnCriticalSystemAlert(string systemName, string message);`
  - В этом же файле написать реализацию `OnCriticalSystemAlert`: выводит в консоль красным цветом штамп тревоги бортового компьютера.
- **Методы:**
  - `CheckSystems()` — проверяет показатели шаттла:
    - Если `_fuelKg < 500`, вызывается `OnCriticalSystemAlert("Топливная система", "Критический остаток топлива!");`
    - Если `_hullIntegrity < 25`, вызывается `OnCriticalSystemAlert("Контур обшивки", "Опасность разрушения корпуса!");`
  - `PrintTelemetry()` — аккуратно форматирует и выводит в консоль сводную таблицу всех текущих параметров корабля.

---

### Файл 4: `Program.cs` (Точка входа)

В методе `Main`:

1. Создать экземпляр челнока с исходными параметрами:
   - Имя: `"Буран-Next"`
   - Топливо: `2400.0` кг
   - Кислород: `48.0` часов
   - Корпус: `100%`
2. Вывести стартовую телеметрию через `PrintTelemetry()`.
3. Смоделировать полетный цикл:
   - Выполнить маневровый импульс `ExecuteOrbitalBurn(15, 8.0)`.
   - Запустить проверку `CheckSystems()`.
   - Выполнить длительный разгонный прожиг `ExecuteOrbitalBurn(60, 15.0)`.
   - Провести вход в атмосферу `PerformAtmosphericEntry()`.
   - Повторно запустить диагностику `CheckSystems()`.
4. Вывести финальное состояние шаттла через `PrintTelemetry()`.
